# 製品コンテキスト：Rec-adio

## 存在理由

Rec-adioは、以下の理由から開発されました：

1. **見逃し防止**：仕事や学校などで、リアルタイムでラジオ番組やライブ配信を視聴できないことがよくあります。Rec-adioは、そのような状況でも後から番組を楽しめるようにします。

2. **アーカイブの不足**：多くの配信プラットフォームでは、配信終了後にコンテンツが削除されたり、有料会員限定のアーカイブになったりします。Rec-adioは、ユーザーが関心を持つコンテンツを自動的に保存します。

3. **プラットフォーム横断**：ユーザーは複数のプラットフォームで配信される番組を視聴することが多いですが、それぞれのプラットフォームごとに異なるツールを使用するのは非効率です。Rec-adioは、単一のツールで複数のプラットフォームをサポートします。

4. **自動化の必要性**：手動で録音を開始・終了するのは手間がかかり、忘れる可能性もあります。Rec-adioは、スケジュールに基づいて自動的に録音を行います。

## 解決する問題

Rec-adioは、以下の問題を解決します：

1. **時間的制約**：リアルタイムで視聴できない場合でも、後から好きな時間に視聴できるようにします。

2. **プラットフォームの制限**：プラットフォームが提供するアーカイブ機能の制限（期間限定、有料会員限定など）を回避します。

3. **複数ツールの管理**：複数のプラットフォーム向けの異なる録音ツールを使い分ける必要がなくなります。

4. **手動操作の手間**：録音の開始・終了を自動化し、ユーザーの負担を軽減します。

5. **ライブ配信の見逃し**：事前に告知されていないライブ配信も、特定のユーザーを監視することで自動的に録音します。

## ユーザー像

Rec-adioの主なユーザー像は以下の通りです：

1. **忙しい社会人・学生**：リアルタイムで番組を視聴する時間がなく、後から視聴したいユーザー

2. **コンテンツアーカイバー**：お気に入りの番組やライブ配信を保存・整理したいユーザー

3. **複数プラットフォームのファン**：様々なプラットフォームで配信される番組を視聴するユーザー

4. **技術に詳しいユーザー**：コマンドラインツールを使いこなせるユーザー（将来的にはGUIも検討）

## 動作方法

Rec-adioは以下のように動作します：

1. **コアサービス（デーモン）**：
   - バックグラウンドで常時動作
   - スケジュールの管理
   - 録音ジョブの実行
   - プラットフォームの監視
   - プラグインの管理

2. **コマンドラインツール**：
   - コアサービスとの通信
   - 録音予約の追加・削除
   - スケジュールの表示
   - 録音済みファイルの管理
   - 設定の変更

3. **基本的なワークフロー**：
   - ユーザーがコマンドラインツールを使って録音予約を追加
   - コアサービスがスケジュールを管理し、適切なタイミングで録音を開始
   - 録音完了後、ファイルを指定されたディレクトリに保存
   - ユーザーが録音済みファイルを視聴

4. **ライブ配信の自動録音**：
   - ユーザーが監視したいアカウントを登録
   - コアサービスが定期的にライブ配信の状態を確認
   - ライブ配信が検出されると自動的に録音を開始

## ユーザー体験の目標

Rec-adioは以下のようなユーザー体験を目指します：

1. **シンプルさ**：複雑な設定なしで、基本的な機能を簡単に利用できる

2. **信頼性**：予約した番組が確実に録音される

3. **効率性**：最小限のリソースで動作し、システムに負担をかけない

4. **柔軟性**：様々なプラットフォームや録音方法に対応できる

5. **拡張性**：ユーザーが新しいプラットフォームのサポートを追加できる

## 競合製品との違い

Rec-adioの差別化ポイントは以下の通りです：

1. **マルチプラットフォーム対応**：単一のツールで複数のプラットフォームをサポート

2. **プラグイン式アーキテクチャ**：新しいプラットフォームを容易に追加可能

3. **軽量設計**：最小限のリソースで動作

4. **オープンソース**：コミュニティによる改善と拡張が可能

5. **コマンドライン中心**：自動化やスクリプトとの連携が容易
