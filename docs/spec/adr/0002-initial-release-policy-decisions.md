# ADR-0002: 初期リリース運用ポリシーの固定

- 日付: 2026-02-10
- ステータス: Accepted

## Context

- 再設計初期は、仕様を絞って安定稼働を優先する必要がある。
- 予約形式や欠損時の扱いを早期に固定しないと、実装とテストの範囲が肥大化する。

## Decision

- 初期リリースは単発予約のみ
- `catch_up_window=15m` を採用
  - 15分以内の取りこぼしは起動時即時実行
  - 15分超過はスキップ
- 同時録音数のデフォルトは `worker_count=2`
- 出力形式は `m4a(aac)` 固定

## Consequences

### Positive

- 実装が小さくなり、品質確保に集中できる
- 受け入れテストが明確化する
- 運用時の予測可能性が上がる

### Negative

- 繰り返し予約は後続リリースまで提供できない
- 出力形式の柔軟性は当面ない
