# 02. 要件定義（To-Be）

更新日: 2026-02-10

## 1. スコープ

- 対象: ローカル常駐デーモン + CLI/GRPC クライアントでの録音ジョブ管理
- 除外: 分散実行、複数ノード協調、クラウドマルチテナント

## 2. 機能要件（FR）

- `FR-001` ジョブ作成: URL/タイトル/録音時間/開始時刻を指定してジョブを作成できる
- `FR-002` ジョブ更新: 未完了ジョブの開始時刻・タイトル・録音時間を更新できる
- `FR-003` ジョブ停止/再開: 有効なジョブを一時停止/再開できる
- `FR-004` ジョブ削除: 実行前ジョブを削除できる
- `FR-005` 即時録音: 従来 `StartFromURL` 相当の即時実行をサポートする
- `FR-006` 実行管理: スケジューラーが到達時刻でジョブをキュー投入する
- `FR-007` 実行制御: ワーカーがキューから取り出して録音を実行する
- `FR-008` 実行キャンセル: 実行中録音をキャンセルできる
- `FR-009` 状態参照: ジョブ一覧/詳細、実行履歴一覧/詳細を取得できる
- `FR-010` 再起動復元: 再起動後にジョブと未完了実行状態を復元できる
- `FR-011` ダウンタイム救済: 停止中に開始時刻を過ぎたジョブは、`catch_up_window` 以内なら起動時に即時実行する

## 3. 非機能要件（NFR）

- `NFR-001` 外部依存最小化: 常時稼働に必須の外部ミドルウェアを持たない（SQLiteのみ）
- `NFR-002` 永続性: ジョブ定義と実行履歴を SQLite ファイルに永続化する
- `NFR-003` 一貫性: 状態遷移は原子的に保存され、不正遷移を防ぐ
- `NFR-004` 可観測性: 主要イベント（作成/更新/キュー投入/開始/完了/失敗/キャンセル）を構造化ログで出力する
- `NFR-005` 障害耐性: プロセス異常終了後に「実行中」残骸を検知して整合回復できる
- `NFR-006` 設定性: 同時実行数、キュー長、DBパス、保存先を設定可能にする
- `NFR-007` 初期運用簡素化: 初期リリースでは録音形式を `m4a(aac)` 固定とする

## 4. 受け入れ条件（AC）

- `AC-001`: 1件の予約ジョブを登録し、予定時刻に録音が開始される
- `AC-002`: 実行前ジョブの時刻を更新すると、更新後時刻で開始される
- `AC-003`: 実行中ジョブをキャンセルすると、短時間で `canceled` へ遷移する
- `AC-004`: デーモン再起動後も未完了ジョブ一覧が復元される
- `AC-005`: `StartFromURL` 実行で即時ジョブが生成され、履歴が残る
- `AC-006`: SQLite ファイルのみで開発/テスト/実運用が成立する
- `AC-007`: 起動時に開始時刻超過ジョブが `15分以内` なら即時実行される
- `AC-008`: 起動時に開始時刻超過ジョブが `15分超過` ならスキップされる

## 5. 制約

- 単一デーモン前提（同一 SQLite を複数デーモンで同時利用しない）
- ffmpeg 実行可能環境であること
- 音源ソースは当面 `URL` のみサポート
- 初期リリースは単発予約のみ（繰り返し予約は対象外）

## 6. 初期リリース固定方針（2026-02-10 合意）

- 予約形式: 単発予約のみ
- 停止中の取りこぼし救済: `catch_up_window=15m`
  - 15分以内: 起動時に即時実行
  - 15分超過: スキップ
- 同時録音数のデフォルト: `worker_count=2`
- 出力形式: `m4a(aac)` 固定
